## 结论摘要

1. **基础 agent 闭环可以在浏览器内实现，不必从零写循环。** Pi agent-core/pi-ai 是明确候选；Nanobrowser 证明 MV3 内浏览器观察与工具循环可行。但两者都不能直接等同 BeeHelper 所需的完整 AI coding 工作台。[研究一](agent-harness.md)
2. **直接移植完整 dsh 到 MV3 不应被视为低成本方案。** dsh 已有浏览器 Worker preview，但其动态模块求值与 Node 兼容层存在迁移成本。Cordis core 的浏览器打包与基本生命周期烟测通过，不等于 dsh 完整产品已在扩展运行。[研究一](agent-harness.md)
3. **PWA 不是 WASM 的前提，也不是权限升级。** 扩展配置 CSP 后即可运行 WASM；PWA 的价值可能在不同的动态代码执行环境、Web 分发和独立工作台，而非自动获得扩展或本地进程权限。[研究二](browser-runtime-boundaries.md)
4. **复用外部完整 harness 可行，但仍需连接层。** ACP、Codex App Server、Claude Agent SDK 分别提供控制入口；浏览器工具、源码、运行与观测结果需要贯通。连接既有运行环境不等于可控制任意客户端或通用复用其订阅额度。[研究三](external-agent-bridge.md)

## 候选方案

| 方案 | 可以复用 | BeeHelper 仍要承担 | 建议 |
| --- | --- | --- | --- |
| Cordis core + Pi core | 插件生命周期、基础 agent loop 与流式事件 | 源码工具、执行/观测、持久化恢复、provider 兼容 | 内置基础 agent 的小型验证候选 |
| dsh 浏览器 Worker preview | harness 浏览器 hosting、VFS 和有限执行设施 | 模型通路、动态装载、微应用改码与扩展工具连接的验证 | 不原样移植特权 MV3；Web/PWA Worker + 扩展值得另行验证 |
| Nanobrowser 相关模块 | 浏览器观察、控制、agent 运行恢复的参考实现 | 微应用创作与管理、源码 patch、插件架构 | 执行层参考，不当作完整 coding harness |
| 外部 harness + 连接器 | 成熟 coding runtime、原生会话和上下文管理 | 安装/连接、浏览器工具桥接、源码状态同步 | 对标现有 AI coding 体验时优先 |

依据与限制见三份研究。这里的候选顺序是工程建议，不是用户已经批准的选择，也不是工期估算。

## 建议的决策方式

- 首版若优先验证“反复对话修改微应用、真实运行、看到效果”，建议先复用外部完整 harness，将研发集中在 BeeHelper 独有的浏览器与微应用能力。
- 首版若要求“只安装扩展、提供模型接口即可 AI 创作”，则优先对 Pi 基础 loop 做一个最小贯通验证，再决定是否承诺内置闭环；不要直接承诺已达到现有 coding 工具的完整成熟度。
- 两种 agent 通过可替换连接器/provider 接入，用户入口均在 BeeHelper。以上是可行的设计方向，尚无集成验证。
- PWA 暂不作为必需依赖；只有识别到明确的动态执行/分发缺口时才加入。需要本地进程或 OS 能力时，另行评估本地程序，而非假设 PWA 可解决。
- dsh 的独立 Web/PWA Worker 是有上游实现依据的组合候选，不能因为它不能原样放进 MV3 就一并否定。对 JS 微应用而言，不支持原生 Bash/npm 也未必阻断任务；本轮尚未完成它与扩展的端到端验证。

## 与已确认需求的关系

- 首批用户为自己与身边多系统操作的同事；微应用先由用户本人制作。
- 微应用类似用户脚本，不限于固定流程；业务默认值和执行策略由作者通过 AI 对话持续调整。
- 支持确定性微应用运行，也支持 agent 探索；创作交互对标 AI coding 工具，源码可见、可改，效果可观察。
- everything-is-a-plugin 是组件组合理念；现阶段不新增企业治理限制，但浏览器 CSP、API 权限和分发政策仍是客观技术/发布边界。
- 首个业务验证样例为测试工具创建店铺、商家入驻、客户后台三步表单；本轮没有设计其业务规则，也没有操作业务系统。

## 已验证与未验证

已验证：官方文档与固定源码快照；Cordis core 的小型 browser bundle 与无 Node 全局 VM 生命周期烟测；研究文档的引用标识与内部链接静态检查。

未验证：真实 Chrome 扩展加载、Pi/provider 在 MV3 的完整依赖闭包、模型请求、跨页面业务链路、外部 agent 会话和工具回传、商店审核。未生成产品代码，未安装项目依赖，未读取凭据或更改 agent 客户端配置。
