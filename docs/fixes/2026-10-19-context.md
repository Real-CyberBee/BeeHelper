# 0.1.1 页面操作与 Agent 上下文修复

日期：2026-10-19。

## 已确认的问题

1. `browser_action` 给 `scripting.executeScript` 传入 `[selector, action, value]`。点击通常不传 value，数组中出现 undefined，Chrome 报 `args index 2: Value is unserializable`。这不是页面权限缺失，也不是模型不能调用工具。
2. 页面观察与操作只查询 document，没有进入开放 Shadow DOM。BeeHelper 自己通过 `bee.mount()` 挂载的悬浮按钮因此也无法被工具观察或点击。
3. 对话原本只有所选微应用和标签页的 ID，没有用途摘要、最近完整运行 ID 或明确能力清单。读取源码工具本来存在，但缺少可靠的发现与上下文指引。
4. `run_get` 找不到记录时直接返回 null，无法区分 appId、缩略 runId、错误 ID 和超过保留范围。本次没有读取用户个人 Chrome 的业务数据，因此不能确定用户那一次 null 的具体原因，不能声称恢复了已丢失记录。

## 修复

- 页面注入改用可 JSON 序列化的命令，点击不再传 undefined。fill/select 缺 value、禁用控件、不支持的控件类型会明确失败。
- 观察和操作共用开放 Shadow DOM 遍历。返回唯一控件引用、下拉选项、checked、readonly、可见性及附件输入元数据；新观察生成新引用，避免旧引用误指向其他控件。
- 新增 `capabilities_get`，与实际 MCP 工具注册清单一致。MCP 初始化提供 server instructions，每轮任务都携带实际能力、所选微应用摘要、真实目标页和最近完整运行 ID。
- 源码仍由 `microapp_get` 读取，页面由 `browser_inspect` 观察。不自动将源码、页面全文或日志正文塞入每轮上下文；未保存编辑会明确标记，不能假装其已被读取。
- 新增 `run_list`。`run_get({runId})` 使用完整运行 ID，兼容旧参数 id；无效 ID 明确报错并提示如何恢复上下文，不再无声返回 null。
- 明确 `active` 只表示已挂载监听/界面，不等于按钮逻辑执行或业务表单填写成功。需实际点击并检查页面、日志。

## 可复现验证

最小命令：

```sh
npx playwright test -g '上下文回归：点击'
npx playwright test -g '上下文回归：观察'
```

修复前分别复现 `Value is unserializable`、观察结果缺失 Shadow DOM 按钮；修复后都通过，并断言实际控件变化与按钮日志，而非只断言请求未抛错。

常规验证：`npm test` 的 16 项测试通过；`npm run test:e2e` 的 13 项本地浏览器用例通过，真实模型用例默认跳过。真实 Codex 上下文回归需显式开启：

```sh
BEEHELPER_LIVE_CODEX=1 npx playwright test -g '真实 Codex 使用微应用和网页上下文'
```

该用例不在用户提示中写工具名或运行 ID，只要求读取所选应用、观察本地网页、点击悬浮按钮并核实日志；会消耗实际模型额度。具体执行结果见[验证记录](../verification.md)。

## 范围

通用支持开放 Shadow DOM，不承诺穿透关闭的 Shadow DOM 或任意跨源 iframe。当前没有内置的文件路径上传工具；附件元数据可观察不等于附件已上传。

未修改用户的业务微应用源码，没有操作真实注册主体、银行字段或提交业务表单。银行账号格式、字段映射和上传策略应在平台能力正常后，结合实际页面由用户继续微调，不能在宿主里硬编码。

升级时先停止运行任务，再重新加载扩展并连接 Codex，以使浏览器执行层、连接器工具和对话指引同时更新；不要卸载清空本地库。

若页面上已显示旧试用的悬浮按钮，先结束旧试用，升级后重新运行微应用，不直接沿用旧实例判断新日志。确需刷新目标页面时，应先保存未提交的表单输入，避免丢失测试数据；本次修复不会自动刷新或提交业务页。
