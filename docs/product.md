# BeeHelper 产品需求

日期：2026-10-18。

状态：产品主方向已确认；已补入随后提出的“直接查看效果与便捷安装”要求。本文不决定尚未验证的底层技术实现。

## 1. 产品定位

面向需要操作多个业务系统的人，在浏览器侧边栏管理、创作、微调和运行微应用。

核心价值是将一次有用的操作或页面增强，变成找得到、能修改、能复用的微应用。用户与 AI 反复对话，直接看到实际效果，再决定是否安装、保存和持续使用。

不是固定流程编排器，也不要求每个微应用都跨多个系统。微应用可以是脚本、页面增强、交互面板、流程或需要 agent 参与的任务。

## 2. 已确认的产品决策

| 事项 | 首版决定 |
| --- | --- |
| 用户 | 自己和身边多系统操作的同事，包括 QA、产品等 |
| 作者 | 微应用先由用户本人制作 |
| 入口 | BeeHelper 侧边栏；页面内提供快捷入口或增强界面 |
| AI | 聚焦外部 Codex，接受安装或连接本地运行环境；其他 agent 后置 |
| 创作体验 | 类似 AI coding 工具：对话、源码修改、执行、观察、继续微调 |
| 微应用自由度 | 借鉴 Tampermonkey 的脚本运行方式，不做兼容，不固化为流程 |
| 源码 | BeeHelper 管理，用户可查看和修改；不要求维护本地工程、IDE 或 Git |
| 本地库 | 搜索、收藏、导入导出、版本记录 |
| 触发 | 主动运行、匹配页面自动激活、页面事件监听 |
| 登录态 | 沿用当前浏览器登录态，不承诺独立账号隔离 |
| 权限原则 | 现阶段不新增企业治理限制；尊重浏览器、运行环境和已有授权的客观限制 |
| PWA | 是否引入由能力验证决定，不作为首版既定依赖 |

## 3. 核心对象

### 微应用

具有明确用途、可运行和可持续修改的能力单元。可以包含描述、适用页面、源码、界面或其他资源、配置、触发方式、版本和运行记录。

这些是管理与执行所需的信息，不是限制业务逻辑的固定流程 schema。是否生成随机数据、提交表单、复用记录或修复失败步骤，由微应用作者决定。

### 候选微应用

AI 生成或用户导入后、尚未加入本地库的微应用。候选可以被查看、编辑、试用或直接安装，不因出现在对话中就自动成为已安装项。

### 安装与保存

本文中的“安装”指把微应用及其必要资源保存到 BeeHelper 本地库，不是再次安装浏览器扩展。安装后可以检索、收藏、再次运行和查看版本。

安装应携带微应用声明的触发配置，并清楚显示是否启用。保存、立即运行和页面自动激活的语义应可区分，具体启用方式按微应用配置和用户选择决定，不额外增加企业审批流程。

## 4. 首版功能

| 编号 | 能力 | 用户可观察的结果 |
| --- | --- | --- |
| F01 | 本地微应用库 | 能搜索、收藏、打开、运行和管理已安装微应用 |
| F02 | Codex 对话创作 | 从 BeeHelper 发起描述、修改和修复，看到流式进度及结果 |
| F03 | 源码与效果反馈 | 可查看、手动修改源码，并对当前版本执行和观察 |
| F04 | 直接查看效果 | 未安装的候选也能展示界面或在目标页面临时试用 |
| F05 | 一键安装/保存 | 从候选或试用结果直接加入本地库，无需导出再导入 |
| F06 | 安装与试用并列 | 可以直接安装，也可先试用；不强制先安装或先完成预览 |
| F07 | 微应用运行 | 支持主动执行、匹配页面激活和页面事件监听 |
| F08 | 版本记录 | 能识别当前源码、历史修改及某次运行使用的版本 |
| F09 | 导入导出 | 可交换微应用包，导入后可选择试用或安装 |
| F10 | 页面上下文 | 当前页面可用入口能带入页面上下文，不必重复描述所有信息 |
| F11 | 运行反馈 | 可看到进度、结果和错误，向 AI 继续说明哪里不符合预期 |

### 便捷安装与即时效果

- AI 产出的候选应有直接操作入口，例如“查看效果”和“安装”，不只返回一段等待复制的代码。
- 简单微应用不要求用户手动创建目录、填写工程配置或执行构建命令。
- 安装时保存用户正在查看或试用的确切源码版本，不混入稍后到达的 AI 修改。
- 对同一个候选，试用和安装沿用同一份内容，不通过两套逻辑重新生成。
- 未安装候选可以继续微调，也可以丢弃；不得悄悄加入已安装库或留下长期自动激活。
- 运行和安装失败应显示真实状态，不以完成聊天回复替代执行成功。

“查看效果”根据微应用类型可以是隔离界面展示，也可以是真实业务页面上的临时执行。后者会产生实际效果；平台不能统一承诺模拟执行、业务回滚或无副作用。

## 5. 主要使用闭环

### 创作、看效果、安装

1. 用户描述用途，Codex 通过 BeeHelper 提供的能力生成候选。
2. 用户直接查看效果，或直接选择安装。
3. 效果不符时继续对话或改源码，再次运行观察。
4. 用户选择安装（保存），当前确切版本加入本地库。
5. 后续从库或页面入口运行，并继续修改、查看版本。

这是一条常见路径，不是强制状态顺序。已有候选可跳过试用直接安装。

### 已安装微应用微调

用户从本地库打开微应用，说明想改什么，看到修改和执行结果。平台记录源码版本；业务参数、生成规则和修复策略不由平台硬编码。

### 无现成微应用

支持 agent 探索任务并按需形成候选，不要求先定义完整流程。是否沉淀为微应用由用户决定。

## 6. 首个业务验证样例

准备 QA 测试数据：在模拟测试工具创建店铺、完成商家入驻，然后填写客户管理后台的三步表单。

该样例用来检验跨页面操作、对话微调、效果观察和便捷安装。以下不在平台层决定：随机规则、提交时机、资源复用、失败后重试与业务修复策略。

真实字段、系统地址和工具接口需在进入样例实现时另行读取核实；当前没有操作任何业务系统。

## 7. 首版不承诺

- 自研完整 agent harness，或内置达到现有 coding 工具全部能力的 agent。
- 连接任意客户端、接管现有 Codex 桌面会话或通用复用订阅额度。
- Tampermonkey/GM API 兼容、任意 npm 包或原生程序直接运行。
- 团队治理平台、云端共享库、安装链接订阅与自动更新中心。
- 定时任务、无人值守执行、独立登录态隔离。
- 自动化任意网站且始终成功；取消、卸载或切换版本能撤销业务操作。
- 只安装 PWA 就获得更高浏览器或操作系统权限。

这些是首版范围或尚未验证的承诺，不是永久限制微应用形态。

## 8. 首版验收原则

- 能在 BeeHelper 内描述、改源码、执行、看效果，不要求维护本地工程。
- 候选未安装也能看效果；试用后可直接安装，也可不试用直接安装。
- 安装内容与当时选定版本一致，进入本地库后可搜索、收藏、导出和再次运行。
- 关闭试用、禁用或卸载时，能够清理平台登记的监听与资源；不承诺撤销外部业务效果。
- 已安装微应用的主动运行与声明的页面触发可用；普通脚本执行不应无故要求 Codex 在线。
- 不把断连、取消或未知执行结果误报为成功，不因恢复连接盲目重放有副作用的动作。
- 本地源码和配置的实际存储、导出范围、版本对应关系对用户可追溯。

## 9. 0.4 增补

| 事项 | 决定 | 理由 |
| --- | --- | --- |
| 视觉 | 蜜蜂黄浅色主题；Logo 使用公司网站 cyberbee.top 的蜜蜂标识 | 与赛博蜜蜂品牌一致，浅色更适合长时间侧边栏使用 |

| AI 工具 | `userscript_search` / `userscript_import` 进入 MCP 工具与能力清单 | 让 AI 先找现成方案，再按用户需求改 |

| 宿主能力 | 微应用可调用 `bee.apps.*` 与其他微应用、`bee.askAI` 呼叫会话 | 支撑“一切皆插件”和 AI 改造自身，但不绕过用户确认 |
